## アプリとWebの改善

ホーム・初回体験、製品サイト、App Store掲載を分担した4エージェントでレビューし、
実装後にホームの操作と保存契約を別エージェントが再確認した。

- Homeにテーマと時間の選択を常設。無料の4種類をその場で選べ、選択だけではタイマーを開始しない。
  既存の長押しとメニューも利用できる。選択中の時間を空の瓶の説明にも反映する。
- 小さいiPhoneで開始ボタンに届くよう瓶の高さを調整。最大文字サイズでは選択を縦に並べ、
  テーマ名を折り返す。まとまり粒の詳細ボタンがある場合は、その高さも確保する。
- 初回案内に手順名と明示的な戻る操作を追加。テーマの選択状況は開始前に常に確認できる。
  毎日20:00のリマインダーとタイマー終了通知を区別し、通知は任意のままにする。
- 初回案内の親アクセシビリティ識別子が子の操作識別子を上書きしていた問題を、
  独立したコンテナ境界で修正した。戻るボタンの実際の操作領域を44pt以上にし、
  選択状況をアクセシビリティ上でも一つのテキストとして扱う。
- iPhone SEで空の瓶の説明と粒数が重なる問題、完走画面の「閉じる」が改行される問題を、
  実際の描画を確認して修正した。
- WebにモバイルメニューとFAQを追加。無料機能、デモ、公開状況へ進めるようにし、
  発売前の無効なボタンを、デモとFAQへ進めるリンクに変更した。
- Webの見出しの不自然な改行、操作領域、キーボードによるメニューの開閉と移動後のフォーカスを改善した。
- WebのHomeとタイマーの紹介画像を今回の実画面に差し替えた。描き足しはせず、
  603×1311pxのWebPへ縮小・変換した（Home約34KB、タイマー約28KB）。
  タイマー画像は帰還通知のUIテストで撮影した、通知タップ後の25分集中（残り24:22・97%）を使用。
  満タンから減るリングと、表示変更の入口を撤去した最終画面に合わせ、1206×2622pxから等比縮小した。
- Webデモを「宝石を追加」から、タイマー開始→集中→完走→宝石の自動記録へ変更した。
  約8秒の早送りであることを開始前から明示し、00:00を見せてから一粒が落ちる。
  一時停止・再開に対応し、中断時は粒を増やさず、別タブへ離れた場合も一時停止する。
  ヒーロー本文と体験リンクでもタイマーが出発点であることを明記した。
- 集中タイマーのリングを満タンから時計回りに減る表示へ変更し、割合も残り時間に合わせた。
  円盤は色の面で残り時間を表し、計測中の画面では時間の数字を表示しない。
- タイマーの見た目は設定の「集中タイマーの表示」から、見本付きの4種類を選べるようにした。
  集中中に設定へ気がそれないよう、タイマー画面の表示変更ボタンと選択画面を撤去した。
  保存した見た目で計測し、最大文字サイズでは設定の見本を1列にする。
- Dynamic Islandの展開表示とロック画面に、集中・一時停止・完了に応じた帰還案内を追加した。
  OSの標準タップでアプリを開き、既存のタイマー維持・保存済み状態の復元を利用する。
- 設定の「集中に戻るお知らせ」は既定オフ。許可してオンにした端末で、集中中にホーム画面や別のアプリへ移ると
  30秒後に一度だけ通知する。復帰時は権限確認より先に予約と表示済み通知を取り消す。
  一時停止・休憩中と、通知時点で終了まで60秒以下になる場合は予約しない。画面をロックしただけのときは、
  パスコードで保護されたiPhoneがロック後に送る通知（protected data）を20秒以内に受けて取り消す。
  パスコードを使っていない端末などでは届くことがあると設定に明示する。
  集中画面がinactiveで破棄されるCloudKit経路でも、プロセス内の候補を残存する起動画面から予約する。
  中断・所有権喪失・アカウント変更・完全削除は、予約中の処理と候補も無効化する。
- 完走後は先に記録と完了メッセージを保存し、Homeの「閉じる」を押してから宝石が瓶の上から落ちる。
  カードが消え、瓶が表示領域に収まってから物理アニメーションを開始する。
  休憩・共有を選んだ場合も、一粒が着地してから次の画面へ進む。
- 完了メッセージの確認待ち・着地待ちを保存し、既存の着地済みメッセージと区別する。
  古い保留記録も最大4 IDを個別に取得し、通常の履歴表示件数の外でも復帰できるようにした。
  「視差効果を減らす」では落下せず一粒を配置し、記録や着地通知を重複させない。

## アクセシビリティの実機評価

`AccessibilityAdversarialUITests` はAX5でHome・menu・overviewを監査するが、全体のVoiceOver操作や
全画面の対応を証明しない。申告する機能ごとに、少なくとも以下を最新の署名済み候補で完走する。

| 共通タスク | 合格条件 |
| --- | --- |
| 初回保存先を選び、テーマ1件でHomeへ進む | 両方の保存先と影響を読める。確認前に選択が確定しない。ためし粒を省略できる |
| Homeでテーマ・時間を変更して集中開始 | 名前・現在値・操作を読み上げる。選択だけでtimerが始まらない。大きい文字でも選択と開始に届く |
| 一時停止・再開・中断・完走・休憩 | 状態と残時間を音や色だけに依存せず把握できる。画面切替後に操作対象へ到達できる |
| 記録・成果・週／生涯の振り返り | 図や瓶の情報を説明文でも理解できる。再集計中と確定値を識別できる |
| 共有を確認し、閉じる | 共有対象と保存／共有の違いが分かる。キャンセルして元の作業へ戻れる |
| Proを開いて閉じる／復元する | 機能・実価格・買い切り・復元・閉じるへ到達でき、エラーと成功を認識できる |
| 設定の変更・データ書き出し・記録reset | 現在の設定を認識でき、破壊的操作は対象と結果が明瞭。確認をキャンセルできる |

文字サイズは200%以上に加え、対応する最大サイズでも確認する。背景4種類と重要画面で文字や
操作部品のコントラストを確認し、テーマや状態は色の違いだけで識別させない。視差効果を減らす設定で
瓶や画面遷移が落ち着き、情報や操作は残ることを確認する。Voice Controlを申告する場合は表示名で
主要操作を呼べることも別に確認する。

Accessibility Nutrition Labelsは各機能の基準を満たすと確認したものだけを下書きする。
対応済みの申告や公開は本レビューでは行っていない。

## 公開後の検証候補

まずApp Store Connectで利用可能な集計値を使い、閲覧からダウンロードへの転換、利用継続、クラッシュを
確認する。新しい追跡SDKは前提にしない。Product Page Optimizationでは、同じ体験の画像順や表現を
一度に一つの仮説で比較し、データ量が不足している間は勝敗を決めない。実施・公開は別作業とする。
