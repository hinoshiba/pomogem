# アプリを離れたときの一時停止と「集中が切れています」（F1）

状態: Phase B（2026-09-26）。オーナーの依頼による変更（Owner-requested change 2026-09-26）です。
既定はオン（オーナー承認、2026-09-26、確定）で、`FocusLeavePolicy.enabledByDefault`の1か所だけで切り替えます。
設定 → 集中の下に2つの切り替えがあり、利用者はいつでも止められます（下の「設定の行」）。

Phase Aで置いていた統合・提出の条件（止める設定がなく、設定画面の「タイマーはバックグラウンドでも止まりません」と
「集中に戻るお知らせ」の説明が事実と食い違う）は、Phase Bの設定の2行と文言の書き換えで満たしました
（`AppStore/submission-checklist.md`）。

> 依頼（原文）: アプリをバックグラウンドにしたら、タイマーを停止して、集中が切れているという通知を定期的に出すようにしよう

## 決まり

- 対象は、この端末が所有する**実行中の集中**だけです。休憩、本人が押した一時停止、終了まで60秒以下の集中には
  何もしません（通知の既存の「終了間際」の区切りと同じ60秒）。
- きっかけはアプリ全体の`scenePhase == .background`だけです。`.inactive`（コントロールセンター、通知センター、
  権限の確認、Face ID、Siri、着信バナー）は離脱ではありません。
- 画面ロックは勉強のための正当な使い方なので、止めません。パスコードのあるiPhoneは、ロックの約10秒後に
  `protectedDataWillBecomeUnavailable`を送ります。`.background`から**20秒**（`lockDetectionWindow`）の間に
  これを受けるか、20秒の時点で保護データが読めなければロックと判定し、タイマーはそのまま進みます。
- 20秒たってもロックの知らせがない場合、またはiOSがバックグラウンド時間を先に打ち切った場合は
  「アプリを離れた」と判定し、**離れた時点**（`leftAt`）にさかのぼって一時停止します。離れていた時間は
  集中に数えません。
- 20秒以内に戻った場合は、ちょっと見ただけとして何もしません。
- パスコードがないiPhoneでは、iOSがロックを知らせないため、ロックとアプリの切り替えを区別できません。
  どちらも「離れた」として一時停止します（オーナー承認。タイマー画面の文言と設定の説明がそう伝えます）。
- 戻っても自動では再開しません。タイマー画面は通常の一時停止表示に
  「アプリを離れていたので一時停止しました」を1行添え、いつもの「再開」で続きから始めます。
- タイマー画面の「終了通知は端末の設定から」（通知が許可されていないとき）で設定アプリを開いた場合は、
  アプリが案内した操作なので離れたとみなしません。ボタンを押してから5秒以内の`.background`だけが対象で、
  1回使えば消えます（`FocusLeaveAppInitiatedDeparture`）。
- 画面の明るさを読む方法や、SpringBoardの非公開通知キーは使いません（審査ガイドライン2.5.1）。
  使うのは公開APIだけです: `scenePhase`、`UIApplication.isProtectedDataAvailable`、
  `protectedDataWillBecomeUnavailableNotification`、`beginBackgroundTask`、
  `LAContext.canEvaluatePolicy(.deviceOwnerAuthentication)`（パスコードの有無を読むだけで、認証画面は出しません）。

## 「集中が切れています」の通知

- `.background`の時点で、次の5件を1回きりの予約として仮に入れます（プロセスはすぐ停止されるため）。
  離れてから +30秒、+2分、+5分、+10分、+20分。それ以上は送りません。
  最初の+30秒はロック判定の20秒より後なので、ロックと判定すれば届く前に取り消せます。
- 識別子は`pomogem.focus.leave-nudge.1`〜`.5`、同じ`threadIdentifier`でまとまります。
  割り込みレベルは`.active`です（Time Sensitiveは集中・休憩の終了だけ）。音は、音の設定がオンなら
  終了通知と同じ短いチャイム、オフなら無音です。テーマ名は含めず、粒の約束もしません。
- 文面（Notificationsテーブル）: タイトル「集中が切れています」。1件目
  「タイマーを一時停止しました。ポモジェムに戻ると続きから再開できます。」、2件目以降は
  「一時停止して5分たちました。戻れば続きから再開できます。」のように、止まっている時間を事実として伝えます。
  責める言葉、連続記録、損失の言い回しは使いません。
- 予約するのは、通知が許可されていて、端末の2つの切り替え（一時停止・通知）がどちらもオンのときだけです。
- 取り消す（予約中と表示済みの両方）とき: 復帰（権限の確認より前）、ロックの判定、中断（今日はここまで）、
  集中の終了、所有権の喪失、アカウントの変更、完全削除、どちらかの切り替えをオフにしたとき。
- 一時停止がオンのあいだ、以前の「集中に戻るお知らせ」（30秒後に1回）は使いません（両方は出しません）。
  一時停止をオフにすると、「集中に戻るお知らせ」は今までどおりに動きます。

## 設定（端末内だけ）

| キー | 設定の行 | 既定 |
|---|---|---|
| `focus.leave-pause.enabled` | 「アプリを離れたら一時停止」 | `true`（オーナー承認） |
| `focus.leave-pause.nudges.enabled` | 「集中が切れたらお知らせ」（「集中が切れています」を送る） | `true`（オーナー承認）。既定がオフになっても、「集中に戻るお知らせ」をオンにしていた人はオン |

どちらも`UserDefaults.standard`だけに保存し、同期・書き出し・Prefsのstampに含めません。
完全削除はUserDefaultsのドメインごと消します。UIテストは、共有Simulatorで多数の集中を背景に回すため、
`POMOGEM_UI_TEST_FOCUS_LEAVE_PAUSE=1`で明示したテストだけが既定オンになります。明示した設定値は常に優先し、
起動引数（`-focus.leave-pause.enabled NO`）で渡る文字列の`NO`・`YES`・`0`・`1`もその値として読みます
（`RealDeviceCoreLoopUITests`はこれでF1をオフにします）。設定の行を切り替えるUIテストが共有Simulatorに
値を残さないよう、UIテストのプロセスは起動時に2つのキーを永続ドメインから消し、それぞれの既定から始めます
（`FocusLeavePreferences.startUITestProcessFromItsDefault`、Debugだけ。起動引数の値は消えず、そのまま優先します）。

### 設定の行（`SettingsView`、設定 → 集中の下）

- 「アプリを離れたら一時停止」: `FocusLeavePreferences.setLeavePauseEnabled`。通知の許可は要りません。
  オフにすると予約済みの「集中が切れています」を取り消します。
- 「集中が切れたらお知らせ」（副題「離れてから20分までに最大5回」。数は`FocusLeavePolicy.nudgeOffsets`から）:
  一時停止がオンのときだけ表示します。`FocusLeavePreferences.setNudgesEnabled`。オンにするには、ほかの通知の
  切り替えと同じく、この端末の通知の許可が要ります（断られたら何も保存しない）。本人が選んだオン
  （明示のオン、または明示の値がなく以前の「集中に戻るお知らせ」をオンにしていた場合。
  `FocusLeavePolicy.nudgesWereChosen`）なのに許可がないときだけ、すぐ下に既存の「許可する」／「設定を開く」の行を
  出します。既定のオンだけでは出しません（ほかの通知の行と同じく、この行は本人の意図に付くもので、選んでいない
  切り替えの下に行動の呼びかけを置かない）。代わりに説明に「このiPhoneで通知を許可していない場合は届きません」と
  事実だけを書きます。
- 説明（切り替えのオン・オフどちらでも正しい文）: オンのとき、ホーム画面やほかのアプリへ移ると離れた時点で
  一時停止すること、20秒以内に戻れば止まらないこと、パスコードがあればロックでは通常止まらないこと（ロック解除の
  直後の再ロックは一時停止することがあり、離れてすぐのロックは止まらないことがある。下の「分かっている限界」）、
  パスコードがないとロックでも一時停止すること、自動では再開せず「再開する」で続きから進むこと、休憩と終了1分前
  からは止めないこと、オフのときはアプリを離れても止まらないこと。タイマー画面の「画面ロック中も通常は進みます」も
  同じ理由で「通常は」を付けます。
- 通知の欄の説明は「「毎日のリマインダー」と「先月の瓶のお知らせ」は既定でオフです」と、その欄の切り替えだけを
  指します（「集中が切れたらお知らせ」は既定オンのため）。
- 一時停止がオンのあいだ、「集中に戻るお知らせ」の行と説明は表示しません（ホストが予約しないため、表示すると
  食い違う）。オフにすると、今までどおり表示して動きます。
- ライブアクティビティの説明の「タイマーはバックグラウンドでも止まりません」は、
  「アプリを離れたときにタイマーを止めるかどうかは、「アプリを離れたら一時停止」の設定に従います」に変えました。
- UIテスト: `FocusLeaveSettingsUITests`（既定オンの構成で行の入れ替わり、既定のオンでは許可の行を出さないこと、
  本人が選んだオンで許可の行の位置と文、許可の要るオンが通るか断られて何も保存しないか、読み戻し、
  既定サイズの行の監査とDynamic Type、AX5での2行・説明3段落・許可の行の到達と文字の欠け）、
  `SettingsPaywallUITests`（既定オフの構成で順序と説明、AX5）。許可の答えはUIテスト用の固定値
  （`POMOGEM_UI_TEST_NOTIFICATIONS_UNASKED`と`POMOGEM_UI_TEST_NOTIFICATIONS_ANSWER`、Debugだけ）で決め、
  Simulatorが以前に答えた内容に左右されません。

## 仕組み

- `FocusLeavePolicy`（純粋な規則）と`FocusLeaveTransition`（保存したタイマーの変化）: 判定、閾値、
  予約の時刻、文言の選択。
- `FocusLeaveMonitor`（起動画面のホスト、`PomoGemApp`）: iCloudの15秒のバックグラウンド猶予で
  RootViewとFocusViewが外れた後も残るため、保存したタイマー（`FocusPersistence`）、`NotificationManager`、
  `FocusActivityManager`を直接操作します。通知の許可がなくても判定は必ず行います（critic A2）。
  所有の証拠は、所有端末のタイマー画面だけが登録する`NotificationManager.registeredRunningFocus`です。
- `.background`で**同期的に**、保存したタイマーへ端末内の記録`leaveExcursion {sessionID, leftAt}`を書きます。
  ロックなら記録を消し、離れたなら`engine.pause(at: leftAt)`と`leavePause {sessionID, pausedAt, plannedEndDate}`を書き、
  終了通知だけを取り消し（「集中が切れています」は残す。critic D7）、Live Activityを一時停止表示にします。
  判定までのバックグラウンド時間は、Live Activityの更新が終わるまで持ち続けて返します。更新の途中でiOSが
  時間を打ち切った場合も、期限切れの処理がその時間を必ず返します（返さないとアプリが終了させられます）。
- **判定より先に適用する規則（critic A3）**: 記録が残ったまま20秒を過ぎていれば「離れた」とみなし、
  `leftAt`で一時停止してから次へ進みます。`FocusPersistence.load`、`preparedForLocalRelaunch`、
  `relaunchAction`、起動画面の状態表示（`peekTimerEnvelopes`、書き込みなし）、タイマー画面の復帰・再表示が
  すべてこれを通るため、プロセスが判定中に終了しても、終了予定を過ぎた集中を完了として保存・加算しません。
- 判定中にプロセスが終了し、本人が20秒以内に戻った場合は、ちょっと見ただけです。iCloudモードでは保存したタイマーを
  読めるのがアカウントの確認後なので、最初に読む時点では20秒を過ぎていることがあります。そのため、この
  プロセスで最初にUIKitが`.active`を確かめた時刻（`FocusLeaveReturnWitness`）を読む側へ渡し、離れてから
  20秒以内の復帰なら記録を消すだけにします。離れる前の起動時刻は、その離脱の証拠になりません。
- タイマー画面は、ホストの一時停止の通知（`FocusLeaveMonitor.didAutoPause`）を同じターンで受けて
  保存済みの一時停止に合わせます。古い実行中の状態で書いても、離れる前の終了予定と同じ実行中の状態は
  保存時に無視されます（`FocusPersistence.mergingLeaveMarkers`）。本当の再開は必ず終了予定より後に終わります。
- 端末内の記録2つはどちらもOptionalで、古い保存データはそのまま読めます。`FocusCloudPayload`には含めません。

## 電力（バックグラウンド時間とタイマー）

- バックグラウンドタスク（`beginBackgroundTask`）を始めるのは、対象の集中（この端末が所有する実行中の集中で、
  残り60秒より多く、切り替えがオン）から`.background`へ移ったときの1つだけです。休憩、本人が押した一時停止、
  終了間際、切り替えがオフ、アプリが案内した設定への移動、判定中の2回目の`.background`では増やしません。
- 持つのは最長で判定の20秒（`lockDetectionWindow`）と、「離れた」と判定した後のLive Activityの更新の間だけです。
  iOSが先に時間を打ち切った場合は、期限切れの処理がその場で返します（返さないとアプリが終了させられます）。
- 返す経路と回数: 「離れた」（Live Activityの更新の後）、ロックの知らせ、20秒の時点で保護データが読めない、
  `.background`の時点ですでにロック中、パスコードなし、20秒以内の復帰、判定が止まった後の復帰、判定中の期限切れ、
  Live Activityの更新中の期限切れ、一時停止するものがなくなった場合、アカウントの境界。どの経路でも1回だけ返し、
  二重には返しません。
- 判定の待ちは`Task.sleep`の1回だけです。窓が閉じると（ロック、復帰、期限切れ、アカウントの境界）その待ちの
  タスクを取り消すので、待ちはすぐに終わり、ロックの知らせの監視も同時に外します。判定の後に残るタイマー、
  繰り返しの処理、`UIBackgroundModes`（音声・位置情報など）はありません。
- その後の「集中が切れています」は、`.background`の時点で予約した最大5件のローカル通知をiOSが配信するもので、
  アプリは起動しません。
- 1回の離脱の費用: 最長約20秒の実行（ほとんどは待機）、保存したタイマーへの小さな書き込み2回（記録と判定）、
  通知の予約と取り消し、Live Activityの更新1回です。
- テスト: `FocusLeaveMonitorTests`の`testEveryWayAWindowClosesEndsItsBackgroundTaskOnceAndKeepsNoTimer`
  （上の全経路で、タスクを1回だけ返す、監視を外す、待ちを残さない、待ちは20秒以内）、
  `testTheLiveWaitEndsAsSoonAsItsWindowIsCancelled`（本番の待ちが取り消しですぐ終わる）、
  `testBackgroundExpiryPausesAndEndsItsTaskAtOnce`、`testExpiryWhileTheLiveActivityUpdateRunsStillEndsTheTaskOnce`。

## iCloudと他の端末（D1.6）

CloudKitのフィールドや同期する列挙値は増やしていません。一時停止の同期行は、この端末が次に前面へ戻って
タイマー画面が保存するときに、通常の経路で書きます。行の`updatedAt`はその書き込み時刻で、残り時間だけが
`leftAt`から決まります。それまで**他の端末には「実行中」に見えます**。他の端末が一時停止済みのタイマーを
引き継ぐ場合は、既存の一時停止の引き継ぎ規則に従います（自己申告あつかい）。

## スクリーンタイムの学習側の休止（D1.10）

本人が押した一時停止は、今までどおり再開・停止まで学習側を休止します。アプリを離れたための一時停止は、
離れた時点の終了予定（`plannedEndDate`）までだけ休止します（この取り引きはオーナーが承認済み、2026-09-26）。そのため、勉強アプリへ移ってそのまま戻らなくても、
予定の終わりを過ぎた利用は勉強アプリの粒として数えます（`ScreenTimeTimerHold.learningPause`）。
どのアプリへ移ったかを即時に知る方法はないため、離れていた間の勉強アプリの利用をタイマーの集中として
数えることはしません。

## 分かっている限界

- 離れてから約10秒以内にロックすると、ロックと判定されます。
- 直前にロック解除していた場合、保護データの知らせが10〜40秒遅れることが報告されています。
  20秒を過ぎれば「離れた」と判定されます。
- ロックの判定後にロックを解除して別のアプリを使っても、アプリには分かりません。
- 判定の20秒より前にiOSがプロセスを終了すると、戻った時点（または次に保存したタイマーを読んだ時点）で
  「離れた」として適用します。そのあいだに元の終了予定が来ると、予約済みの終了通知が一度届くことがあります。
- 長い一時停止: 記録の開始から終了までの幅は7日まで（`StudySessionIntegrityPolicy`）です。7日を超えて
  放置された集中の扱いは既存の一時停止と同じで、F1では変えていません。

## 実機での確認（iPhone 12 mini、iOS 26.3.x）

Simulatorはデータ保護がなく、ロック後の`protectedDataWillBecomeUnavailable`を再現できず、XCUIDeviceは
ロックボタンを押せません。単体テストの合格だけでは閉じず、次を**パスコードあり・なしの両方**で確認します。

| 操作（25分の集中中） | パスコードあり | パスコードなし |
|---|---|---|
| サイドボタンでロックし、1分後に解除して戻る | 進んだまま。通知なし | 離れた時点で一時停止。約30秒で1件目 |
| 自動ロック（「タイマー中は画面をロックしない」をオフ） | 進んだまま | 一時停止 |
| ホーム画面へ移り、10秒で戻る | 何も起きない | 何も起きない |
| ホーム画面へ移り、1分後に戻る | 離れた時点で一時停止。30秒で1件目。戻ると通知が消え、画面に1行 | 同じ |
| 別アプリへ移り、25分以上放置してから戻る | 5件（+30秒〜+20分）で止まる。完了にならず一時停止のまま | 同じ |
| コントロールセンター／通知センター／Face ID | 何も起きない | 何も起きない |
| 着信（応答して通話） | 通話アプリが前面なら「離れた」扱い | 同じ |
| 手動の一時停止中・休憩中にホーム画面へ | 何も起きない | 何も起きない |
| 残り60秒以下でホーム画面へ | 何も起きない（終了通知が届く） | 同じ |
| 離れて一時停止した後、Live Activity | 「一時停止中」表示 | 同じ |
| iCloudモードで離れて1分後に戻る | 画面は再構成され、一時停止と1行が出る。他端末は戻るまで「実行中」 | 同じ |
| 通知を許可していない | 一時停止だけ行い、通知なし | 同じ |
