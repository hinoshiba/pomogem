# iCloudモードのオフライン利用 — 設計と検証中の範囲

更新日: 2026-09-12

この変更は開発・検証中です。審査待ちの1.0.1 (7)には含まれません。

## 利用者の動線

通信確認のためにタイマーや記録を長時間使えなくしないことを目的とします。
iCloudを選択した状態と、その時点で同期できるかどうかを分けます。

| 状況 | 動作 |
| --- | --- |
| 初回で端末に確認済みデータがない | iCloudの確認・取得が必要。起動全体の待機は30秒で区切り、再試行できる画面にする |
| 以前に利用できた端末データがあり、通信できない | 同じ端末の保存領域を同期なしで開き、タイマー・記録・設定を利用する |
| 通常のiCloud画面を使っている最中に通信が切れた | 表示と端末への記録は続ける。通信の回復後はシステムが同期を再試行する |
| 電波はあるがiCloudへの応答が遅い | 起動全体の待機を12秒で区切る。安全に開ける端末データがあればオフライン利用へ進む |
| この起動中に同期用の保存領域を一度開き、閉じた後で通信できなくなった | 同期処理の停止を保証できないため、同じファイルを同期なしで開き直さず、アプリの終了・再起動を案内する |
| オフラインで利用中 | 「このiPhoneに保存・同期は待機中」と表示。接続確認だけで同期完了とは表示しない |
| 同期なしで利用している画面から別のアプリへ移り、戻る | 同じ端末データと画面を保持。復帰時に端末の利用条件を再検証し、通信があれば画面を残したまま接続を確認する |
| 同期なしの端末データで起動した後、通信が回復 | 端末の記録を表示したままアカウント・保存先・リセット履歴を確認し、確認できた後に同期を再開する |
| 別端末でデータが置き換わった／履歴が変わった | 端末の変更を保護し、自動送信を停止。古いデータでiCloudを上書きしない |
| アカウント変更が確認された | オフライン利用の許可を永続的に失効させる。再起動だけでは解除せず、オンラインで本人確認する |
| 保存先切り替え・取消・復旧の途中 | 専用の復旧を優先。オフライン起動を迂回路として使わない |

保存先の切り替えはオンラインで行います。オフライン利用は「このiPhoneのみ」へのモード変更では
なく、iCloudモードの同期待ちです。アプリ自体を削除すると未送信の記録は失われます。

## 実装の境界

- 同期を伴うコンテナは、現在のApple Accountと確認済みの保存先が一致した後に作ります。
  タイムアウトやネットワークの到達性を、この許可へ変換しません。
- オフライン利用には、確定済みのcloud選択、過去の正常マウント、完全な保存領域の組、正常な
  スキーマと永続的な利用記録が必要です。未知・破損した情報は削除して作り直しません。
- オフラインのコンテナは同じstore URL・構成名を使い、CloudKitを`.none`にします。
  新しいnamespaceへのコピー・snapshot再インポートで、同期履歴を作り直す方式ではありません。
- 書き込み可能なコンテナを公開する前に、オフラインで利用したことを永続化します。
  次のCloudKitコンテナを作る前に、保存先の世代とリセット履歴を確認します。
- 通常のiCloud利用後も未送信の変更が残り得るため、次の同期用コンテナを作る前の履歴確認は
  オフライン利用フラグにかかわらず、旧版から引き継ぐデータを含むすべての確認済み端末データで行います。
  サーバーの履歴が以前の確認結果から変わっていれば、端末の現在の履歴を読み取り専用で比較します。
  既に端末へ反映済みの正規のリセットまで、古い確認結果だけで停止させないためです。
  読み取りエラーを「履歴なし」に置き換えることはありません。
- 古いオンライン確認の遅延応答が、途中で受けたアカウント変更を取り消さないよう、
  利用記録には比較交換と改訂IDを使います。アカウント変更は通知と明示的なAPIエラーの両方で扱います。
- 同期なしで既に公開した画面だけは通常のバックグラウンド移行で保持します。復帰時は保存先・
  利用記録・失効・切り替え処理の有無を再検証します。アカウント変更通知や失効の確認では画面と
  書き込みを停止し、通常の同期用コンテナの退役条件は緩めません。
- 起動処理は個々の通信ではなく、単調時計による一つの絶対期限を共有します。
  期限切れ時は最初に起動の世代を無効化し、遅い成功・失敗が画面や許可を変更することを防ぎます。
- タイムアウトは、まだ生きているコンテナの解放を意味しません。以前の同期処理が残ったまま
  同じファイルをオフラインで開かないため、コンテナの退役とプロセス内の同期履歴も確認します。
  同じプロセスで同期用コンテナを一度でも作った場合、弱参照が解放されていてもオフライン用
  コンテナを作りません。この制約により、オンライン利用後にバックグラウンドへ移り、通信の
  ない状態で戻った場合などは再起動が必要です。すべての復帰が途切れずに使えるとは扱いません。
- 既に同期用コンテナを開いている間の、システムによる自動再接続・送受信は、この起動前確認の
  対象外です。別端末との変更を原子的に排他できるという保証や、すべての未送信データの受領確認とは
  区別します。同期の接続確認・起動成功を、アップロード完了として表示しません。

AppleはSwiftDataの`.none`による自動同期停止を説明しています。
[SwiftDataの同期](https://developer.apple.com/documentation/swiftdata/syncing-model-data-across-a-persons-devices)
また、Core Dataでは同期を無効にする間もpersistent historyを保持する必要があります。
[Apple Frameworks Engineerの説明](https://developer.apple.com/forums/thread/118924)
これだけでSwiftDataの同一プロセス内の退役・再構成まで検証済みとは扱いません。
履歴の比較には、Appleが説明する読み取り専用の`ModelConfiguration`を使います。
[WWDC23: Dive deeper into SwiftData](https://developer.apple.com/videos/play/wwdc2023/10196/)
`allowsSave: false`による利用者データへの保存禁止を、共有メモリや内部管理情報も含むすべての
ファイルのバイト不変、または以前の同期処理の停止保証へ広げて解釈しません。

## 確認結果

- 起動期限・遅延応答・オフライン利用記録・旧版の記録の引き継ぎ・履歴確認・保存先構成・
  マウント許可・CloudKit adapterのSimulatorテスト87件が成功。実際のSQLite保存領域で、
  読み取り専用コンテナから同期元・端末専用データへの保存が両方とも拒否され、再読込後も
  データが変わらないことを含みます。
- ライフサイクル修正後の単体テスト全体は1,152件中1,146件成功、明示的な実機専用6件skip、失敗0件。
  Release構成のSimulator arm64／x86_64解析も成功。
- オフラインの通常サイズ・AX5・再試行・自動同期の説明を使うUI fixtureの4ケースが成功。
  バナーを小型化し、全文をスクロールできる別画面へ移し、閉じる操作も44pt以上で届くことを確認。
  通常アプリの実機動作を、このfixtureの成功だけで検証済みとは扱いません。
- Developmentの実機で、既存CloudKit storeと同じURLを`.none`で開き、テーマの変更、
  テーマと記録の追加、成果の削除を保存。60秒間保持し、iCloudの全同期元データが変わらないことを確認。
- 次の新しいプロセスで同じURLのCloudKit同期を再開し、全11種類の端末データと全7種類の
  同期元データを比較。追加・変更・削除がすべて反映されたことを確認。
- 前後で両storeのUUIDが維持され、同期元のnative persistent historyにオフラインの変更が
  追加され、再同期後も履歴が維持されていることを確認。
- 実機Developmentで、製品の読み取り専用factoryから既存の全11モデルと最新リセット履歴を読む
  試験が成功。読み取り専用で10秒間保持し、両storeのUUID・native履歴・データ・DB/WAL/SHMの
  バイトと、全7モデルのサーバーデータに変化がないことをその実行で観測しました。
- 専用ホストで同じプロセスの同期あり→同期なし→同期ありも観測。同期なしの63秒間は
  サーバーの全同期元データと同期イベントに変化がなく、再同期後の全データが一致しました。
  これはその実行の観測結果です。過去の同期処理が常に停止済みだというAPI上の保証にはならず、
  製品の同一プロセスでの再構成を許可する根拠にはしていません。

実機の上記確認は通常の画面を起動しない専用テストホストで行い、ネットワーク接続は維持しています。
本物の通信断、通常画面からの操作、バックグラウンド復帰、アカウント変更、旧版からの実機移行、
複数端末での競合、未送信データがある状態での途中終了は引き続き検証が必要です。
実データ・アカウント情報・端末識別子・署名・生ログは非公開の検証記録に保持します。
