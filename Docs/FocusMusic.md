# 集中用の音楽（Apple Music）

状態: 2026-10-14。取り組みごとの音楽と自動再生設定、非公開の自作プレイリストを含む
Apple Musicライブラリからの選択に対応しました。既存の共通設定・お気に入り・共有リンクも引き継ぎます。

## 好きな音楽・取り組みごとの設定

- Homeの取り組み・時間のすぐ下に「音楽」を表示し、現在の取り組みで使う音楽名（未選択なら「選ぶ」）を出します。
  タップで選択シートを大きく開き、現在の取り組みが設定先になります。設定から開くと共通の音楽が設定先です。
- シートの「音楽の設定先」で共通／取り組みを選びます。指定のない取り組みは共通の音楽を使い、取り組みを指定して
  一覧から選ぶとその取り組みだけに保存します。「共通の音楽を使う」で個別指定を解除できます。
  タイマーの選択画面と開始時の自動再生も、その集中の取り組みに対応します。
- 取り組みの編集では、音楽と自動再生をそれぞれ個別に設定できます。どちらも未指定なら共通設定を
  引き継ぎ、自動再生を明示的にオフにした取り組みは共通設定がオンでも自動再生しません。
  編集中は下書きで、保存したときだけ端末設定へ反映します。音楽を選んで保存してもその場では再生せず、
  キャンセルした選択はお気に入りにも保存しません。
- 「好きな音楽を追加」でApple Musicの曲・アルバム・プレイリスト・ステーションを名前から検索できます。
  検索ボタンを押したときだけ必要な許可を尋ねます。検索結果は保存せず、選択したカスタム音源やハートで
  追加した音源だけがお気に入りに残ります。検索にはMusicKitのカタログアクセスが必要です。
- Apple Musicの共有リンクからも追加できます（`https://music.apple.com`の4種類だけ）。
  アルバムの`?i=`付き共有リンクはその曲として扱います。任意の表示名を付けられます。
  リンクは開かず、カタログIDを読み取ります。
- 「自分のプレイリストから選ぶ」を押したときだけ、必要なApple Musicの許可を確認してプレイリストの名前とIDを
  読み込みます。公開リンクのない自作プレイリストも選択できます。100件ずつ全ページを取得し、
  最初のページだけで一覧を打ち切りません。一覧は画面のメモリ内だけに置き、選んで保存した音楽だけを
  端末内に保存します。全曲一覧や再生履歴は取得せず、プレイリストも作成・変更しません。
  再生時は保存したライブラリIDをMusicKitで解決し、カタログIDへの置換や無関係な音楽への代替をしません。
  再生開始には、従来どおりApple Musicへのアクセス許可と登録状況の確認が必要です。
- お気に入りはおすすめより上に表示します。ハートで外しても、共通／取り組みの音楽指定と、解決に必要な
  ID・表示名・ライブラリIDは残します。再生中のミュージックアプリも止めません。選択中の音源は
  「選択中」に残り、標準候補ならおすすめに戻ります。もう一度選ぶだけではお気に入りに戻らず、
  ハートまたは「お気に入りに追加」で戻せます。
- 個人で指定した音源が再生できない場合は案内を表示し、無関係なおすすめへ自動で切り替えません。
  下記5つのおすすめについては、従来の候補順による代替再生を維持します。

## 同じ先頭から繰り返さない再生

- 「シャッフルで再生する」は既定オンで、次にプレイリスト／アルバムのキューを作るときに適用します。
  MusicKitで取得した最初の曲一覧から開始曲をランダムに選び、以後は全体の曲順をシャッフルします。
  長いプレイリストの全ページ取得を待たずに再生を始めるため、開始曲の候補は最初に取得した範囲です。
  MusicKitのカタログが利用できない場合のMediaPlayer代替では、開始曲もミュージックアプリに任せます。
- この起動中に選んだ音源で、再生を開始したキュー内の項目IDも一致している間は、同じ音源をもう一度
  押してもキューを作り直しません。一時停止中なら続きから再開します。曲名では同一性を判断しません。
  項目IDが変わった場合は、外部でのキュー変更と自然な次曲への移動を区別できないため、以前の音源との
  対応を破棄します。その後、一覧から音源を明示的に選ぶと、その音源でキューを作り直します。
- ポモジェムの一時停止ボタンで止めた場合は、その時点の項目IDと選択中の音源を覚えます。両方が同じままなら、
  自然に次の曲へ進んだ後に止めた場合も、再生ボタンでその続きを再開できます。外部で項目が変わった場合や
  別の取り組みの音源へ切り替えた場合は、古い一時停止を引き継ぎません。停止済み・アプリ再起動後も
  保存された音源から新たに再生します。MediaPlayerの代替経路ではキュー項目の同一性を確認できないため、
  同じ曲のIDだけを根拠に以前の音源の続きとは扱いません。
- ステーション／ラジオの番組・曲順はApple Musicが決めるため、シャッフルの対象にはしません。
  続きからの再開と「次の曲」を使えます（スキップできるかはステーション側によります）。
- 自動再生は引き続き任意・共通設定の既定はオフです。すでに音楽や他の音声が流れているときは、取り組みが変わっても
  自動では入れ替えません。シートからの選択では、指定した取り組みの音楽へ手動で切り替えられます。

オーナー要望（F4）: 「Apple Musicのクラシックチャンネルとかをさっと出せるようなUI導線が欲しい」。

## 動き

- 集中・休憩タイマーの見出しの右側、回転アイコンの隣に音符アイコン（44 × 44pt、`timer.music`）を置きます。
  - Apple Musicが使えて音楽を選んであれば、タップで再生／一時停止します。
  - ミュージックアプリが再生中なら、登録状況に関係なく（確認中・確認できない・登録なしでも）タップで一時停止します。
    VoiceOverのラベルとアイコンは、タップで実際に起きること（一時停止・再生・選ぶ）に合わせます。
  - まだ選んでいない、許可や登録が必要などのときは、タップで「集中用の音楽」シートを開きます。
  - タップで再生を試して始まらなかったとき（案内が出た、登録や許可の状態が変わった）も、シートを開いて理由を見せます。
  - 長押し、またはVoiceOverのアクション「音楽を選ぶ」でも、いつでもシートを開けます。
  - 再生中はアイコンがスピーカーに変わり、アンバー色になります。
  - 集中・休憩の残り1秒になるとシートは（アニメーションなしで）閉じ、終わった後も開きません。
    終了アラートの「止める」ボタン、VoiceOverのフォーカス移動、Magic Tapがシートの下に隠れないようにするためです（#32）。
- 設定 → 集中の最後の行「集中用の音楽」（`settings.focus-music`）でも同じシートを開きます。行には選んだ音楽の名前
  （この起動中にシートがカタログの名前を読めていればその名前、読めていなければ下の一覧の名前、まだ選んでいなければ
  「未選択」）を出します。行を表示するだけでは許可を尋ねず、登録状況の確認やカタログの取得もしません
  （シートを開いたときに行います）。
- シートには、ミュージックアプリで再生することとApple Musicの登録が必要なこと、許可・登録の状態、
  再生中の曲名と再生／一時停止・次の曲、音楽の一覧、「集中を始めたら再生する」を表示します。
- 再生は`SystemMusicPlayer`で「ミュージック」アプリに任せます。ポモジェムは前面のままで、
  音楽を自分のaudio sessionで鳴らさず、Now Playingにもならず、`UIBackgroundModes`の`audio`も持ちません
  （瓶や完了の効果音用の`.ambient`のsessionは従来どおりで、ミュージックの再生を止めません。終了アラームを
  「最大」にした場合、アプリ内のアラームは鳴っている間だけ音楽を小さくし、止めると元の音量に戻します）。そのため
  タイマー画面を離れず、アプリを離れたときの一時停止（F1）も起きません。
- 集中の画面から開いたシートには、アプリの外へ移るものを置きません。設定の「アプリを離れたら一時停止」（F1、
  [FocusLeavePause.md](FocusLeavePause.md)、既定オン）がオンのとき、集中中にほかのアプリへ移ると集中が一時停止する
  ためです。music.apple.comなどへのリンクはなく、許可が拒否・制限されているときも「設定」アプリを開くボタンの
  代わりに「集中が終わってから…」の説明だけを出します。ミュージックアプリを開く・サインインするよう案内する
  文も、「休憩のときなどに…」と休憩を勧めます（どちらも説明だけで、ミュージックアプリを開くボタンはありません）。
  集中の画面は、集中の後の短い休憩・長い休憩でも同じ扱いで、「設定」アプリを開くボタンを出しません。
  「設定」アプリを開くボタンは、集中が動いていない画面（Homeから始めた休憩の画面と設定の入口。Homeの
  入口も同じ）から開いたときだけ出します。休憩はF1の対象外なので、その休憩の画面から「設定」アプリへ移っても
  何も止まりません。
- 集中や休憩が終わっても、終了アラームが鳴っても、音楽は止めません（2026-09-26の決定）。F5の終了アラームは
  鳴っている間だけ音楽を小さくする（duck）だけにする予定で、ミュージックアプリの再生はそのまま続きます。
- Proの機能ではありません（App Review 4.5.2／4.10）。

## 状態と表示

| 状態 | シートの表示 |
|---|---|
| 未確認（`notDetermined`） | 「Apple Musicへのアクセスを許可」。このボタンか一覧のタップでだけ許可を尋ねます（一覧のタップは許可の後そのまま再生します） |
| 拒否（`denied`）・制限（`restricted`） | 理由と「設定」アプリを開くボタン（集中の画面からは説明だけ）。一覧は選んでおくだけで、再生の印（▶︎）を出しません |
| 登録なし（登録できる） | Appleの`musicSubscriptionOffer`（`.playMusic`のお試し・登録の画面。曲やプレイリストは指定しません）を開くボタン。再生・一時停止・次の曲のボタンは出さず、一覧のタップも登録の画面を開きます |
| 登録なし（登録できない） | 再生できない旨。一覧は選んでおくだけで、再生の印を出しません |
| 登録状況を確認できない | 再確認のボタン。一覧のタップでは再生も試し、始まれば「再生できる」として扱います（オフライン時や、MusicKit App Serviceが無効で登録状況を読めない場合に備えるため） |
| 再生できる | 再生中の曲名、再生／一時停止、次の曲 |
| 再生に失敗 | 「休憩のときなどに『ミュージック』アプリを一度開いてから…」の案内（iOS 26.4系の既知の不具合への対処。集中中にミュージックアプリへ移るとF1で集中が一時停止するため、休憩を勧めます） |
| Apple Musicにサインインしていない | 「休憩のときなどに『ミュージック』アプリでApple Musicにサインインすると…」の案内（サインインはミュージックアプリで行うため、上と同じ理由で休憩を勧めます） |

- 表示を開いたとき・タイマー画面を開いたときは状態を読むだけで、許可の画面を出しません。
- シートを開くたびに登録状況を確認し直しますが、確認中も前の答えを使い続け（一覧のタップはすぐ再生）、
  確認に失敗しても分かっている答え（再生できた実績を含む）を捨てません。確認できて答えが変わったときだけ更新します。
- 許可があれば、登録状況に関係なく、ミュージックアプリが再生中・一時停止中の音楽を一時停止・再開・次の曲で
  操作できます（ミュージックアプリの標準の操作で、再生する内容は入れ替えません）。
- 同時に来た確認（シートを開いた直後のタップ、起動直後の自動再生など）は1回の確認を共有し、
  どの呼び出しも答えが出た後の状態を読みます。
- 再生を始める間はほかの再生操作を受け付けませんが、一時停止だけはいつでも受け付け、始まった再生も止めます。
  取り組み編集の下書き選択はこの再生待ちには拘束されません。
  MediaPlayerの準備（`prepareToPlay`）が10秒たっても終わらないときは失敗として案内を出します。
- キャンセルは再生開始前と非同期取得後に確認します。ライブラリ一覧を閉じると読み込みTaskをキャンセルし、
  次のページは取得しません。取得中のシステム処理が即座に終わることまでは保証しません。
  `prepareToPlay`のコールバック待機はキャンセルだけでは即時解除されず、完了または最長10秒の期限まで待ちます。
  その後のキャンセル確認で`play()`へ進むのを防ぎます。共有中の登録状況確認も完了を待ちますが、
  キャンセルされた自動再生は確認結果が戻っても再生しません。

## 集中を始めたら再生する（任意・既定はオフ）

- その集中の取り組みに有効な自動再生設定がオンのとき、このiPhoneで集中を始めた直後（開始から15秒以内）に、
  その取り組みに有効な音楽を1回だけ再生します。個別指定がなければ、それぞれ共通設定を使います。
- 許可や登録が必要な状態では何もしません（許可を尋ねず、登録画面も出しません）。
- ミュージックアプリでもほかのアプリ（ポッドキャスト、ほかの音楽アプリなど）でも、音楽や音声がすでに
  再生中なら入れ替えません（`AVAudioSession`の`isOtherAudioPlaying`を読むだけで、sessionの設定や有効化はしません）。
  音楽の読み込み中にほかの音声を開始した場合も、キューを設定する直前とMediaPlayerの準備完了後に再確認し、
  自動再生を見送ります。案内やエラーは出しません。手動で音源を選ぶ操作は、明示的な切り替えとして扱います。
- 復元・再開・画面の作り直しでは再生しません。iCloudで別のiPhoneから引き継いだ集中は、始まった直後でも
  再生しません。同じ集中で2回目は再生しません（最後に自動再生した集中のIDを保存しています）。
- 登録状況を確認できないときも再生しません（推測で再生しません）。

## 保存するもの

このiPhoneのUserDefaultsだけに保存し、iCloud同期・JSON書き出し・保存先の移行には含めません。

| キー | 内容 |
|---|---|
| `music.focus.source` | 共通の音楽のApple Music ID（既存の選択はそのまま引き継ぐ） |
| `music.focus.saved-sources` | カスタム音源のID・種類・表示名・任意のライブラリID。お気に入りを外しても音楽指定の解決用に保持 |
| `music.focus.unfavorited-sources` | お気に入り表示から外したID。未保存なら従来の保存音源をお気に入りとして表示 |
| `music.focus.subject-sources` | 取り組みUUIDと音楽IDの対応 |
| `music.focus.subject-autoplay` | 取り組みUUIDと自動再生オン／オフの個別指定。未指定なら共通設定 |
| `music.focus.shuffle` | コレクションのシャッフル（未保存ならオン） |
| `music.focus.autoplay` | 「集中を始めたら再生する」 |
| `music.focus.autoplay.last-session` | 最後に自動再生した集中のID（同じ集中で二度鳴らさないため） |

内部の完全削除処理では、ほかのUserDefaultsとともに消去し、この実行中に並べた音楽の記録も忘れます。
ミュージックアプリの再生は利用者のものなので止めません。お気に入りの表示名は端末内に保存します。再生中の曲名・状態・再生履歴は保存・送信しません。
ライブラリのIDは `library:` で始まる保存用IDに分け、同じ文字列のカタログIDと取り違えないようにします。
既存のお気に入りJSONにライブラリIDがなくても読み込めます。SwiftDataやCloudKitの保存モデルは変更しません。

## オーナーの作業が必要なこと

1. **MusicKit App Service**: Certificates, Identifiers & Profiles → Identifiers → `com.hinoshiba.pomogem`
   → App Services → MusicKitを有効にします（Account HolderかAdmin。Appleの審査なし、entitlementと
   provisioning profileの変更なし、Family Controlsのprofileに影響なし）。
   - 有効にするまでMusicKitのdeveloper tokenが発行されず、カタログの取得が失敗します。その間は
     `MPMusicPlayerController.systemMusicPlayer.setQueue(with: [ID])`でプレイリストだけを再生します
     （Appleは推奨していない方法です）。ステーション（クラシックステーション）は再生できず、次の候補へ進みます。
     表示名も上の日本語名のままです。

2026-09-26に決まったこと:

- `NSAppleMusicUsageDescription`の文言「タイマー画面から『ミュージック』アプリで集中用の音楽を再生するために使います。」は承認済みです。
- 一覧の内容と順序は上の表で確定です。
- 集中の終わりと終了アラームで音楽を止めません（F5はduckだけ）。
- 設定の入口を加えました（Homeの入口は2026-10-12に追加）。
- Web版プライバシーポリシー（`http_dists/index.html`の`#privacy`、日本語と英語）に、ミュージックアプリの再生の操作だけで
  開発者へ何も送らないことを1文で加えました。

2026-10-14の取り組み別設定・自作プレイリスト選択への対応:

- 許可の利用目的を「集中用の音楽を再生し、自分のライブラリからプレイリストを選ぶために使います。」へ更新します。
  ライブラリを読むのは一覧を選ぶ明示操作の後だけで、画面表示やタイマー開始による許可要求は追加しません。
