# 瓶の向きと重力（F3）

オーナーの要望（2026-09-26）：「iPhoneを横やひっくり返して使った時に、gemの発生させ方や瓶の中の移動の方向の重力を気にして欲しい」。

瓶の宝石は、iPhone を横にしたり逆さにしたりしたときも、実際の重力の向きに動きます。瓶のデザインと省電力の約束（Docs/GemExperienceDesign.md の §7.8 と §7.13）は変えません。
Home と瓶は縦向きに固定されたままです（`PomoGemAppDelegate`）。そのため、端末の軸と瓶の軸は同じです。

## 重力

- **向きと強さ**：Core Motion の重力を瓶の座標に移します（`JarGravityMapping`）。宝石は、いちばん低い画面の縁へ向かって落ちます。強さは瓶の重力と同じ7.2で、横向きも上向きも許します。
- **机に置いたとき**：画面の面内にある重力が11.5°未満なら、既定の下向きの重力を使います。30°以上なら、感知した重力だけに従います。その間は滑らかにつなぎます。
- **廃止した制限**：「いつも下向きの力を少し残す」制限（`tiltGravityMinimumDownward`）はなくしました。
- **名前を変えた定数**：`tiltGravityHorizontalScale` は光の尺度だけを表すようになったので、`tiltLightHorizontalScale` に改名しました。
- **平滑化と上限**：平滑化（毎秒30回で0.16）と、重力の上限9.4はそのままです。平滑化するのは感知した値のほうで、瓶に移した後の重力ではありません。

## 口と入り方（儀式）

- **口**：見た目は開いたままです（蓋なし、D2）。物理では、口の縁は常に閉じています。重力が上を向いても、粒は瓶から出ません。
- **新しい粒は必ず口から入る**：側面や床から現れることはありません。
  - 完走の粒は、画面の上端から首の中央を落ちます。このときは端末の向きに関係なく、瓶自身の下向きの重力で落ちます（`SKFieldNode` の重力場。単位も積分も物理世界の重力と同じ）。
  - その間は壁を無視しますが、粒は首の中に保たれます。以前は、横向きの重力が首の外へ運んでしまい、着地しない不具合がありました（critic D10）。
  - それ以外の新しい粒は、口のすぐ下に現れます。
- **銅の首輪を過ぎた後**：体全体が首輪の下に入ったら壁が戻り、そこからは端末の重力に従います。
  - 横向きなら、その側の壁へ流れます。
  - 逆さなら、見えない蓋に向かって戻り、そこで落ち着きます。
  - 蓋の側に山があるときは、粒は山と重ならなくなるまで、同じ重力で山の間を通り抜けます（最大1.5秒）。それから山に加わります。

## 着地

Home の受領、完走の落下のガード（`hasCompletionDropInFlight`）、オンボーディングの体験の着地（2.5秒で待つのをやめる）は、どれも着地に頼っています。着地は次のどれかで起きます。

- 床、または着地済みの粒に触れる（従来どおり）。
- 壁や蓋に触れていて、重力がそこへ押し付けている（接点が重力の向きから60°以内）。既定の重力では、壁に触れても着地にはなりません。
- 触れていなくても、新しい粒が0.2秒間、秒速12pt以下のままでいる。重力がほぼ0になる姿勢や、まだ着地していない粒の上で止まったときのためです。

入ってくる途中（儀式の間）の粒は着地しません。

## タップ・揺らし・VoiceOver

- タップ・揺らし・VoiceOver の操作は、重力に逆らう向き（`JarGravityMapping.launchDirection`）に投げます。
- タップの上の余裕、跳ね上げの前のすき間、強制的に戻す動き、揺らしの速さの上限も、重力に合わせた座標（`JarGestureFrame`）で測ります。
- 縦に持ったときは、この座標が画面の x・y と完全に一致します。そのため、動きは従来と同じです。
- VoiceOver の「左・右」は、画面の左右のままです。

## 光と山

- **光**：画面に固定されています。グリントとガラスの反射は、感知した横向きの傾きに従います（`JarGravityMapping.lightHorizontal`）。机に置いていても従います。
- **ジェムベッド**：どの向きでも床にあります。
- **山の光**：床に積もった山では、従来どおり床の帯です。壁や蓋に積もった山では、粒に付いていきます。
- **核の帯（`JarPileClearance`）**：山が床以外に積もっているときは、倍率を下げません。倍率の上限も持ち上げません。床に戻って落ち着いたときに、改めて判定します。`PebbleRadiusPolicy` と `JarScalePolicy` は変えていません。
- **共有**：支えの判定には、山が落ち着いたときの重力を使います。シートが Home を覆うと、モーションが止まって重力は元に戻りますが、止まった山は動きません。
- **床以外の山の共有**：床以外に積もった山は、立てた瓶のカードでは側面や口に貼り付いて見えます。そのため、カードは自分で描く瓶を使います（`ShareJarSnapshotPolicy.pileRestsOnTheFloor`）。

## 省電力（§7.13）

- **止まっている瓶**：モーションは毎秒5回、背景キューで受けます（従来どおり）。
- **メインスレッドへ移るとき**：次の3つだけです。
  - 光を閾値0.015より大きく動かす傾き。Reduce Motion のときは、従来どおりこれでは移りません。
  - 揺らしの山。
  - **向きの変化（新規）**：次の2つがそろったときです（`JarGravityMapping.needsResettle`）。
    - 山が落ち着いたときの姿勢から、端末が約6°以上回った。`wakeDelta` が0.1gを超えることで判定します。センサーの値で測るので、手の震え（±0.012g）ではどの姿勢でも越えません。読んでいる間の手の揺れ（数度）でも越えません。
    - 瓶の重力の向きも3°以上変わった。置く、持ち上げる、後ろへ傾けるだけの動きは強さしか変えないので、瓶は起きません。
- **起きた後**：向きの変化で起きた瓶は、有界の操作ウィンドウ（3秒で落ち着き、5秒で強制的に止まる）の間だけ物理を動かします。山は新しい重力で落ち着き直し、そのときの姿勢が次の基準になります。
- **増やしていないもの**：常時動くタイマーや、メインスレッドで受けるモーションは増やしていません。Home が隠れているとき、または学習の粒がないときは、従来どおりモーションそのものを止めます。
- **Reduce Motion と演出の強さ「控えめ」**：光のふるまいは従来どおりです。Reduce Motion では光が動かず、控えめではグリントが点きません。物理は同じで、向きの変化ではどちらの設定でも瓶が起きます（Docs/EngagementArchitecture.md の、Reduce Motion で物理を変えない約束）。

## Simulator での確認

Simulator にはモーションのハードウェアがありません。そのため、次の環境変数を使います（Debug、UI テストの起動のときだけ）。

- `POMOGEM_UI_TEST_MOTION=synthetic` と `POMOGEM_UI_TEST_GRAVITY=portrait,landscape-left@4,upside-down@12,portrait@20`：姿勢を順に保ちます。秒数は、瓶が最初にモーションを受けてからの時間です。
  - 使える姿勢は portrait、landscape-left、landscape-right、upside-down、flat、face-down です。
  - モーションの観測（速さの切り替えと、止まっている瓶の向きの判定）を通ります。
- `POMOGEM_UI_TEST_MOTION=synthetic` を付けない場合は、`JarFrameProbe` が姿勢を毎秒30回、瓶の重力入力へ直接渡します。
- `POMOGEM_UI_TEST_SPRITE_STATS=1`：記録の各行に、今の重力（`g=dx,dy`）と、山が床にあるか（`floor=1`）が入ります。沈降プローブ（`POMOGEM_UI_TEST_SETTLE_PROBE`）の余白が口の下の余白を表すのは、`floor=1` のときだけです。

## テスト

- `JarOrientationGravityTests`：`SKRenderer` で実際の物理を動かして、次を確かめます。
  - 横・逆さ・切り替えの間も、どの体も瓶から出ない（60fps と30fps）。
  - 完走の粒と内側の粒が口から入り、すべての姿勢で着地する。
  - 入る途中で端末を回しても、首から外れない。
  - オンボーディングの瓶（240×320）の体験の着地が2.5秒以内。
  - 計画プレビューの復元が瓶の中に収まる。
  - 向きの変化で止まった瓶が起き、震えや置く動きでは起きない。
  - Reduce Motion・控えめでも物理が同じ。
  - タップと揺らしが重力に逆らう向きに投げる。
  - 床以外の山で核の帯が倍率を下げない。
  - 共有の判定。
  - 最悪ケースの fixture で、下向きの重力のときに口の下の余白が15%以上（11回の沈降の最小値）。
- `JarGravityMappingTests`：変換そのもの（Phase A）。
- `JarIdleEnergyTests`：省電力の約束。
